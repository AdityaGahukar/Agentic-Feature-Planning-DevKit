Agentic Feature Planning DevKit

A portable, evidence-driven planning engine for agentic workflows. Generates complete, repository-aware implementation blueprints without modifying application code.

MVP Verified (29/29 Tests Passing) Zero External Runtime Dependencies Strict Non-Mutation Guarantee

1. What is the Agentic Feature Planning DevKit?

The Agentic Feature Planning DevKit is an autonomous, repository-aware framework designed to solve the critical "planning gap" in agentic software engineering.

When developers give an AI agent a feature problem statement (e.g., "Add retry handling to payment API"), agents often rush to modify code immediately, causing hallucinated paths, broken conventions, circular dependencies, and regressed tests.

The DevKit inserts a rigorous, automated planning phase prior to code modification. It inspects the codebase, classifies the repository archetype, extracts empirical conventions, breaks the feature down into a dependency-ordered directed acyclic graph (DAG), generates explicit validation specifications, and subjects the entire plan to deterministic quality gates.

Core Philosophy: The DevKit separates planning from implementation. It creates a self-contained, reproducible Blueprint under .devkit/plans/<feature-slug>/ inside the target repository that any engineer or subsequent agent session can execute with zero ambiguity.

2. Problem It Solves

Without DevKit (Ad-Hoc Agent Coding)

  • Jumps immediately into writing code.
  • Hallucinates non-existent modules or file paths.
  • Invents new coding styles ignoring existing conventions.
  • Produces circular, un-orderable implementation steps.
  • Lacks acceptance criteria and automated test mappings.
  • Fails mid-way when context runs out or sessions reset.

With DevKit (Structured Planning)

  • Enforces read-only repository inspection before planning.
  • 100% path grounding against disk inventory (QG-H1).
  • Empirical 7-dimension convention extraction.
  • Topologically sorted DAG verified via Kahn's algorithm (QG-H2).
  • 100% bidirectional traceability from FRs to Tasks and Tests.
  • Fresh-session resume via persistent checkpoints in .devkit/.

3. Key Capabilities

  • Single-Agent Autonomous Pipeline: Advances through all 8 planning stages without needing repetitive human confirmations between stages.
  • Strict Source Code Non-Mutation: Planning writes exclusively to .devkit/. Zero source files, tests, or build outputs are modified.
  • Deterministic Quality Gates: Hard gates (path grounding, acyclicity, traceability, non-mutation) fail the run if hallucinated or invalid.
  • Multi-Archetype Intelligence: Automatically classifies codebases into App, Library, Data Engineering, Infrastructure, Monorepo, or Unknown.
  • Portable, Zero-Binary Architecture: Core planning logic consists of pure Markdown instructions, schemas, and rubrics. Runs on standard LLM toolkits.
  • Session & History Independence: Interrupted runs resume cleanly from disk checkpoints without conversational context.

6. Eight-Stage Planning Pipeline

Every planning run advances sequentially through 8 discrete stages:

Stage Name Primary Objective Output Artifact
Stage 1 Intake & Clarification Validate inputs, generate URL-safe slug, check collisions, filter Critical Ambiguities (Tier 4). .devkit/run-state/intake.md
Stage 2 Repository Reconnaissance 4-pass read-only scan of manifests, directory layout, and test framework; score archetype points. repo-map.md, repo-type.md
Stage 3 Architecture & Conventions Empirically extract 7 convention dimensions (file naming, layout, error idioms, etc.) with code samples. architecture.md, conventions.md
Stage 4 Feature Specification Synthesize user stories (US), functional requirements (FR), testable acceptance criteria (AC), and scope. .devkit/plans/<feature-slug>/feature-spec.md
Stage 5 Impact & Risk Analysis Compute blast radius, map affected components, tag [NEW FILE] paths, and populate Risk Register. implementation-plan.md (Section 1)
Stage 6 Task Decomposition & DAG Decompose into atomic TASK-xxx cards with grounded paths; wire Mermaid flowchart DAG. task-breakdown.md
Stage 7 Validation Planning Map 100% of AC-xxx items to explicit TC-xxx test specs aligned with detected test framework. validation-plan.md
Stage 8 Quality Gates & Finalization Execute Hard Gates (QG-H1..H5) and Soft Gates; write decisions.md and run-summary.md; promote log and purge run-state. decisions.md, run-summary.md, plan-run.log
Full pipeline breakdown available in docs/diagrams/planning_workflow.mmd

9. Evidence-Based Repository Intelligence

The DevKit enforces strict epistemic standards through the 4-tier Evidence Rubric:

Tier Category Definition & Constraint Action Required
Tier 1 Evidence-Supported Corroborated by explicit files, manifests, or tests in the target repository. Cite source file path (e.g. Evidence: `src/auth.ts`). Proceed autonomously.
Tier 2 Reasonable Assumption Standard industry default consistent with the detected framework. Tag as [ASSUMPTION: reasonable-default]. Proceed autonomously.
Tier 3 Design Choice Subjective engineering decision made by the agent among valid options. Document as formal ADR in decisions.md with rejected alternatives.
Tier 4 Critical Ambiguity Contradictory or missing core requirement that fundamentally blocks planning. Trigger interactive Q&A pause (max 1 pause, max 5 questions). Proceed upon reply.
Convention Precedence Rule: Target repository code always overrides external framework conventions. If a codebase uses custom folder naming, custom casing, or a custom error pattern, the DevKit strictly mirrors the repository pattern.

10. Harness Independence

The core planning engine resides completely in core/ and has zero knowledge of Antigravity or any proprietary agent platform. It executes using four generic primitives:

  1. Workspace Access & Sandboxed I/O: Read access to repo root; write access strictly restricted to .devkit/.
  2. Instruction Injection: Injects core/orchestrator.md as the primary agent prompt.
  3. Human Clarification Relay: Relays Tier 4 questions to the user in interactive runtimes (or chooses safe defaults in headless mode).
  4. Tool Independence: Operates using standard file read/write operations without requiring background daemon processes.

Currently, a production adapter is provided for Google Antigravity (adapters/antigravity/). Adapters for Claude Code, Cursor, and Copilot CLI can be implemented against the contract in adapters/generic_contract.md.

11. Checkpoint & Recovery Protocol

The DevKit is immune to session context resets, agent quota cuts, or process interruptions:

stateDiagram-v2
    [*] --> CheckpointCheck: Invocation with (repo, statement)

    state CheckpointCheck {
        InspectRunState: Read .devkit/run-state/stage-log.md
        HashValidation: Validate SHA-256(statement)
        InspectRunState --> HashValidation
    }

    CheckpointCheck --> NewRun: No run-state found
    CheckpointCheck --> HashMismatch: Hash mismatch (different feature)
    CheckpointCheck --> ValidResumption: Hash matches (interrupted run)

    state HashMismatch {
        PurgeOld: Purge stale .devkit/run-state/
        LogWarning: Log safety warning
        PurgeOld --> LogWarning
    }
    HashMismatch --> NewRun

    state ValidResumption {
        DetectStage: Read last COMPLETED stage
        FastForward: Skip completed stages
        DetectStage --> FastForward
    }

    NewRun --> Pipeline: Start at Stage 1
    ValidResumption --> Pipeline: Resume at interrupted stage

    state Pipeline {
        ExecuteRemainingStages: Execute remaining stages autonomously
    }

    Pipeline --> Interruption: Process halted
    Interruption --> [*]: Checkpoints preserved on disk

    Pipeline --> Complete: Stage 8 Completes
    state Complete {
        Promote: Promote stage-log.md to plan-run.log
        Purge: Delete temporary run-state files
        Promote --> Purge
    }
    Complete --> [*]: Blueprint Ready

12. Deterministic Quality Gates

Before any plan is finalized in Stage 8, it must pass 5 Hard Quality Gates:

Gate ID Gate Name Validation Rule Enforcement Utility
QG-H1 100% Path Grounding Every target file must exist on disk or be explicitly tagged [NEW FILE: path]. Zero fabricated paths. tests/unit/path_grounding.py
QG-H2 Task DAG Acyclicity The task dependency graph must be a valid DAG with zero circular dependencies (Kahn's algorithm). tests/unit/dag_validator.py
QG-H3 Requirement Traceability 100% of FR-xxx requirements in feature-spec.md must map to at least one TASK-xxx card. tests/unit/traceability_validator.py
QG-H4 Validation Traceability 100% of AC-xxx acceptance criteria in feature-spec.md must map to at least one TC-xxx test specification. tests/unit/traceability_validator.py
QG-H5 Source Code Non-Mutation Zero file modifications outside .devkit/. Application code and existing tests must be 100% untouched. tests/integration/test_non_mutation.py

13. Current MVP Scope & Limitations

Distinguishing Current MVP Capabilities from Future Possibilities:
  • Supported Archetypes (Current): Heuristic classification for App, Library, Data Engineering, Infrastructure, and Monorepo. Highly obscure, multi-root, or bespoke polyglot repositories fall back gracefully to Unknown.
  • Execution Environment (Current): Google Antigravity Skill Adapter is fully implemented and tested. Other harnesses (Cursor, Claude Code) currently require prompt injection per adapters/generic_contract.md.
  • Distribution (Current): Local workspace skill copying (`.agents/skills/feature-planner/`) or global Antigravity configuration. The DevKit is not currently published on an external public marketplace or package registry.
  • Language & Framework Independence (Current): Does not compile or execute application code; analyzes text files, AST-like structures, and manifests. Works across TypeScript, Python, Go, Rust, Java, and others.

14. How to Get Started

To start using the DevKit in an existing project in under 5 minutes:

# 1. In your project, copy the feature-planner skill:
mkdir -p .agents/skills/feature-planner
cp -r /path/to/agentic-feature-planning-devkit/adapters/antigravity/* .agents/skills/feature-planner/
cp -r /path/to/agentic-feature-planning-devkit/core .agents/skills/feature-planner/

# 2. In Antigravity chat, simply ask:
"Plan feature: Add rate limiting to the login endpoint to prevent brute-force attacks"

# 3. Review your complete implementation plan in:
# .devkit/plans/login-rate-limiting/
